## 1. Обязательные доработки по факту (записал, когда удалишь баги)

- **Supabase (облачная БД)** — подключён и работает. Конфиг `js/supabase-config.js` (`enabled: true`), слой данных `js/db.js`, схема `supabase-schema.sql`. Регистрация: **реальная проверка email через OTP-код** — `DB.sendEmailCode` (`signInWithOtp`), `DB.verifyEmailCode` (`verifyOtp`, type `email`), затем `DB.finishRegistration` (ник + пароль через `updateUser` + insert профиля). **Лимиты Free-плана Supabase:** встроенная почта — **2 письма/час** (мало), OTP-эндпоинт — **360 кодов/час**, повторная отправка — раз в 60 сек. Для промышленного режима — свой SMTP (30 писем/час) или сторонний OTP-сервис. В Supabase НЕ включать «Confirm email» при входе по паролю.
- **Перенос данных на облако (Supabase)** — сделано:
  - **Уведомления** (колокольчик) → таблица `notifications` (`DB.listNotifications/pushNotification/markNotificationsRead/removeNotification`), фолбэк на localStorage.
  - **Комментарии на профилях** → таблица `profile_comments` (`DB.listComments/addComment/updateComment/removeComment`), лайки/дизлайки и редактирование синхронизируются с БД.
  - **Обращения (тикеты)** → таблица `tickets` (`DB.listTickets/createTicket/updateTicket`).
  - **Сервера** → таблица `servers` (`DB.listServers`), магазин берёт сервера и товары из `products`/`servers`.
  - **Банлист** → таблица `bans` (`DB.listBans`) — таблица отображается на bans.html.
  - **Команда** → таблица `team` (`DB.listTeam`), **Префиксы** → таблица `prefixes` (`DB.listPrefixes`) с цветом.
  - Все методы имеют фолбэк на localStorage — сайт не ломается без облака.
  - TODO: RLS для записей уже настроен в `supabase-schema.sql`; выполнить скрипт в SQL Editor, чтобы таблицы создались.
- **Админка** — сделана: страница `admin.html`, доступ по уровням: **1 — хелпер** (только обращения), **2 — администратор** (всё кроме выдачи админки), **3 — создатель** (ещё и уровни админов). Разделы: Уровни админов (только создатель), Сервера, Банлист, Обращения (ответ от «Администрации» + уведомление игроку, закрытие/переоткрытие, фильтр «Активные/Закрытые»), Команда, Правила, Префиксы (с цветом и приоритетом, выдача игроку). Все таблицы — CRUD через `DB.adminUpsert/adminDelete` (Supabase), без облака — локальное хранилище `mc:admin:{таблица}`. Ссылка «Админ-панель» в микро-меню аккаунта.
- **Привилегии в профиле** — `js/player.js` (renderPrivilege): показываются ВСЕ выданные привилегии из `profiles.privileges` (кроме стандартной «Игрок»); если привилегий нет — показывается стандартная «Игрок». `js/players-data.js` теперь тянет профили из Supabase (`DB.findPlayerByName`) с кэшем в localStorage (`mc:db-cache:v2`, TTL 5 мин) — привилегии, скины и баннеры из БД видны на player.html. В БД уже выдана привилегия «Создатель» (BuShiZm, Crystals) с сервером **TechoMagicRPG** и красным цветом `#ff3b3b` — красит имя профиля, надпись и полоску.
- **Цвет префикса для админов** — СДЕЛАНО вместе с админкой: в админке у префикса задаются цвет и владелец (ник); цвет красит ник владельца в шапке (`js/main.js`, кэш `mc:prefix-colors`) и в профиле игрока (`js/player.js`). Кэш обновляется на всех страницах и при изменении в админке.
- **Магазин привилегий** (`shop.html` + `js/shop.js`) — СДЕЛАНО: вкладка «Магазин» в шапке между «Сервера» и «Личный кабинет»; полоска выбора сервера (вся ширина, скруглённая, после выбора плавно сжимается и уезжает в правый верхний угол); привилегии с аккордеонами «Команды»/«Киты», **наследование по старшинству** (у привилегии хранятся только свои команды/киты, вышестоящая автоматически получает всё от нижестоящих, метка «от X»); слайдер срока 1/3/6/12 мес; покупка за рубли (`balanceRub`) через RPC `purchase_privilege` (списание + выдача мгновенно, защита RLS/security definer); при нехватке средств — модалка со ссылкой на `topup.html`. Настройка — в админке (вкладка «Магазин», уровень 2+): привилегии (название, сервер, старшинство, цена, цвет, описание, команды/киты, порядок, вкл/выкл) и настройки DonatePay.
- **Пополнение баланса (DonatePay)** — СДЕЛАНО: страница `topup.html` + `js/topup.js` (выбор суммы, кнопка «Проверить оплату», история, «Тестовый платёж (демо)»), вебхук `api/donatepay-ipn.js` (Vercel serverless). Схема: сайт создаёт «ожидающий платёж» в таблице `donations` и генерирует код **NC-XXXXXX**; игрок пишет код в сообщении доната; вебхук проверяет HMAC-SHA256-подпись, находит платёж по коду и вызывает RPC `credit_donation` (только service_role) — рубли начисляются. Ссылка доната берётся из `site_config.donatepay_url` (полная, напр. `https://donatepay.eu/don/49274`) — при открытии сумма и код подставляются параметрами `?amount=..&message=..` (полуавтомат: плательщик вводит только карту; если DonatePay не подхватит message — код вписывается вручную). Тестовые платежи включаются флагом `site_config.demo_payments='1'` (RPC `demo_credit`) — **перед релизом выключить**. **Деньги — только для создателя (3 уровень админки):** блок настроек DonatePay и корректировка баланса игрока скрыты для уровня 2, RPC `admin_set_balance` требует `admin_level >= 3`. **TODO:** проверить точный алгоритм подписи и поддержку `?message=` по дашборду DonatePay (веб-поиск на момент написания недоступен, схема в `api/donatepay-ipn.js` помечена комментарием). ИП/ООО/самозанятость для DonatePay не нужны (приём/вывод — физлицо по паспорту, у самого DonatePay юрлицо казахстанское ТОО NAUR-GROUP).
- **Правила** — теперь читаются из таблицы `rules` (`DB.listRules`): секции `project`/`servers`, заголовок + текст. Фолбэк — статические аккордеоны. Редактирование — в админке.
- **Переименование проекта** — финальное название **NOVACRAFT** (`js/main.js` `PROJECT_NAME`), менять не будем.
- **Реальные ссылки Discord / Telegram** — в шапке (меню «три полоски»): **Discord** `https://discord.gg/mMhmkgExNM`, **Telegram** `https://t.me/NOVACRAFT2` — обе актуальны.

### api/donatepay-ipn.js — вебхук DonatePay (Vercel serverless)
- Vercel-функция (без npm-зависимостей, Node runtime). URL задаётся в настройках DonatePay → Уведомления (IPN). Принимает POST form-urlencoded: `notification_type`, `operation_id`, `amount`, `currency`, `message`, `signature`. Проверяет подпись **HMAC-SHA256(секрет, "type:op_id:amount:currency:message")** (TODO: сверить точную схему с примером из дашборда DonatePay), находит код NC-XXXXXX в сообщении и вызывает RPC `credit_donation` с service_role ключом.
- Переменные окружения Vercel: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `DONATEPAY_SECRET`. Без `DONATEPAY_SECRET` — dev-режим (подпись не проверяется, warning в логах).

### prefixes.html — префиксы (новая страница)
- Переключатель «Доступные / Закрытые» (слайдер). С Supabase префиксы берутся из таблицы `prefixes` (`DB.listPrefixes`), у префикса: название, цвет, приоритет (красит ник при priority > 0), порядок. Владельца у префикса НЕТ: «доступные/закрытые» считаются персонально — выдан префикс игроку или нет (`profiles.prefixes`).
- Страница: «Доступные» = выданные тебе (кнопка «Надеть» / «Снять», один активный через `profiles.active_prefix`), «Закрытые» = все остальные. Надетый префикс пишется после ника в открытом профиле. TODO: `/api/prefixes`.
